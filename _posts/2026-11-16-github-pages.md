안녕하세요\~

첫 글에서는 블로그를 시작한 이유와 앞으로 기록할 내용을 소개했는데요.  
이번 글에서는 다른 플랫폼들과 비교했을 때 왜 GitHub Pages를 선택했는지, 블로그를 어떻게 만들었는지 적어보려고 합니다.

## 블로그 플랫폼 비교

개발 공부를 기록할 때 많이 사용하는 플랫폼으로는 벨로그, 티스토리, GitHub Pages 이렇게 3가지가 대표적인데요.

| 플랫폼 | 장점 | 고려할 점 |
| --- | --- | --- |
| 벨로그 | Markdown과 코드 블록을 지원하고, 설정 없이 바로 개발 글을 쓸 수 있음 | 사이트 디자인을 자유롭게 바꾸기 어려움 |
| 티스토리 | 스킨과 HTML·CSS를 수정할 수 있고, 애드센스 연동도 가능함 | 원하는 디자인을 만들려면 스킨과 설정을 손봐야 할 수 있음 |
| GitHub Pages | 코드와 글을 함께 관리하고, 사이트를 자유롭게 꾸밀 수 있음. 커밋으로 잔디도 채울 수 있음 | 초기 설정과 Git 사용법을 익혀야 하고, 방명록 같은 기능은 별도로 연결해야 함 |

→ 요약하자면

**벨로그:** 글쓰기에 집중하기 좋은 플랫폼

**티스토리**: 운영 편의와 꾸미기, 수익화를 함께 고려할 수 있는 플랫폼

**GitHub Pages:** 사이트 구성과 코드 관리까지 경험할 수 있는 방식

이라고 보시면 됩니다.

저는 공부 기록을 남기는 것 뿐만 아니라, **블로그를 나만의 공간처럼 꾸미고 관리하고 싶어** GitHub Pages를 선택하게 되었습니다. (그리고 깃허브 잔디도 심겨서 기분이 좋습니다. ㅎㅎ)

## GitHub Pages와 Jekyll는 어떤 관계일까?

**GitHub Pages**는 GitHub 저장소에 있는 파일을 웹사이트로 공개할 수 있는 서비스이고, `github.io`는 기본 사이트 주소에 사용되는 도메인입니다.

저는 글을 쉽게 관리하기 위해 **Jekyll**을 함께 사용하고 있습니다. Jekyll은 Markdown으로 작성한 글과 화면 틀을 합쳐 웹페이지로 만들어주는 도구입니다!

| **구성요소** | **역할** |
| --- | --- |
| GitHub 저장소 | 사이트 코드와 게시글을 보관 |
| Jekyll | Markdown 글과 레이아웃을 웹페이지로 변환 |
| GitHub Pages | 만들어진 웹사이트를 공개 |
| HTML·CSS·JavaScript | 화면과 버튼, 미니룸 같은 기능을 구성 |

게시글은 `_posts` 폴더에 Markdown 파일로 작성합니다. 평소 노션을 써서 Markdown이 익숙한 점도 좋았습니다. 작성한 파일을 저장소에 올리면 **Jekyll**이 웹페이지로 만들고, **GitHub Pages**가 공개합니다!

사이트의 기능도 직접 연결해야 했는데, 이때 기능마다 저장 방식을 다르게 했습니다.  
방문자와 내용을 공유해야 하는 **방명록**은 **별도의 저장 공간을 연결**했고, **미니룸** 배치처럼 제 설정만 기억하면 되는 정보는 **브라우저에 저장**했습니다.

## GitHub Pages 후기

처음 설정할 때는 손이 좀 가지만, 화면부터 아이템의 기능까지 직접 바꿀 수 있다는 점이 재미있었습니다. 글만 쓰는 블로그를 넘어 작은 웹 프로젝트를 만들고 있다는 느낌이 들었습니다.

제가 원했던 **나만의 공간을 직접 만들고 관리하기**에는 **GitHub Pages**가 잘 맞는 선택이었던 것 같아요.
